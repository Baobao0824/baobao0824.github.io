## 第一章 面试的流程

这本书中要求你先写出单元测试用例，然后写解决问题的函数，我认为这种观念已经过时了，因为现在多是这个acm模式，不可能出现单元测试这种情况。

通常来讲的面试环节：行为面试、技术面试、应聘者提问。

首先是行为面试，面试者会注意到应聘者的性格特点。他一般首先会让你做一个简短的自我介绍，不用太长时间，用30秒到一分钟的时间介绍一下自己主要的学习工作经历即可。在自我介绍之后，面试官一般会借着对照应聘者的简历去详细了解他感兴趣的项目，可以按照STAR模式来介绍。

+ S即situation，简短的项目背景。
+ T是task，自己完成的任务。在用词上要区分参与和负责，一般来说负责对应的是总体框架设计和核心算法，而只写了几行代码肯定就算作参与了。
+ A是Action，为完成任务做了哪些工作，是怎么做的。如果你做的是系统设计，那么可以介绍系统架构的特点；如果是开发，那么就可以写基于什么工具在哪个平台下应用了哪些技术。
+ R即Result，是自己的贡献，最好能用数字加以说明，例如按时完成了多少功能、性能提高百分比是多少、修复了多少个bug。

例如作者在Winforms项目的经历：Winforms是微软.NET中的一个成熟的UI平台，本人的工作是在添加少量新功能之外主要维护已有的功能。新的功能主要是让Winforms的控件风格和Vista、Windows 7 的风格保持一致。在维护方面，对于较难的问题，我用WinDbg等工具进行调试。在过去的两年中，我共修改了超过200个bug。

除此之外，面试官最常问的问题包括：

+ 你在该项目中碰到的最大问题是什么，你是如何解决的？
+ 从这个项目中你学到了什么？
+ 什么时候会和其他成员（包括开发人员、测试人员、设计人员、项目经理等）有什么样的冲突，你们是怎么解决冲突的？

当你在简历上写掌握的技能时，也要规定自己的技能掌握程度。技能大概分这几个等级。

+ 了解，只是上过课或者看过书，没有做过实际的项目，除非这个职位需要，否则建议不要写。
+ 熟悉，使用某项技术已经有相当长的时间，查阅相关的文档可以独立解决大部分的问题。毕设和项目开发中的过程就算是熟悉。
+ 精通，如果开发过程中别人问我们的问题，我们也可以解决，那么就可以说是精通，轻易不要写。

虽然我目前还在校，但是还是要准备一下，当别人问你为什么跳槽的时候，你应该如何回答。首先要做的就是不要流露出负面的情绪，避免回答下面这几种原因：

+ 老板太苛刻。如果面试官就是你未来的老板，那么面试官把你招进来，她认为他也可能在你嘴里变得苛刻。
+ 同事太难相处。如果你这么说，那么面试官会认为你这个人本身就很难相处。
+ 加班太频繁。我说实话还是要装出一个奋斗比的样子出来。
+ 工资太低。还是那句话，装奋斗逼就不要提钱。

作者给了你一个万能模板：现在的工作做了一段时间，已经没有太多的激情了，因此希望寻找一份更有挑战的工作。

在这之后就开始了重头戏，也就是技术面试的环节，这对面试结果起着决定性作用，这东西到底考察什么能力我就不写了，都是废话。不过我们要考虑到一点，就是是否考虑到了各种特殊的边界条件，应该在动手写代码之前想好各种测试用例（但是我说实话现在的面试那么快，肯定是你先把冒烟测试跑出来然后在说别的）

当你一眼看不出问题隐藏的规律时，你可以用一两个具体的例子来模拟操作过程。对于程序员来说，需要具备很好的学习能力才能跟上知识更替的步伐。通常面试官有两种方法考察应聘者的学习能力。第一种就是问应聘者最近在看什么书，从中学到了哪些新技术。第二种方法就是抛出一个新概念，看你能不能在短时间内理解这个新概念并解决相关的问题。

在结束面试前的5到10分钟，面试官会给应聘者机会问几个问题，这个是看你关心的问题能不能给面试官留下更好的印象。因此可以自己尝试着准备几个问题。不过有一些问题还是不建议问的。

+ 不要问公司的大方向战略。首先这和你一个一线开发没关系，问题和你的切身利益没有多少关系，并且面试官自己可能也不知道。
+ 不要问工资，还是那句话，奋斗逼就不要明面上提钱我说实话。
+ 不要立即打听面试结果，这个可能不是他一个人能决定的，问了他也没法说。

推荐问的是与应聘职位或项目相关的问题。例如作者去思科面试，最后一轮是老板面试，他介绍说正在招聘的项目组负责开发一个测试系统，思科用他来测试供应商生产的网络设备，作者问的问题是：这个组是做系统测试的，那这个组的人员是不是也要参与网络设备的测试？是不是要学习与硬件测试相关的知识？因为我们测试的是网络设备，那么这个职位对网络硬件的掌握程度有没有要求？

作者还给我们举了一个`sizeof`的例子。

> 面试官（A）：定义一个空的类型，里面没有任何成员变量和成员函数。对该类型求sizeof，得到的结果是多少？
> 
> 应聘者（B）：答案是1。
>
> A：为什么不是0？
>
> B：空类型的实例中不包含任何信息，本来求`sizeof`应该是0，但是当我们声明该类型的实例的时候，它必须在内存中占有一定的空间，否则无法使用这些实例。至于占用多少内存由编译器决定。在visual studio（这就显出外行来了，vs怎么能是编译器呢）中每个空类型的实例占用1字节的空间。
>
> A：如果在该类型中添加一个构造函数和析构函数，再对该类型求`sizeof`，得到的结果又是多少？
>
> B：和前面一样，还是1.调用构造函数和析构函数只需要知道函数的地址即可，而这些函数的地址只与类型相关，而与类型的实例无关，编译器也不会因为这两个函数而在实例内添加任何额外的信息。
>
> A：那如果把析构函数标记为虚函数呢？
>
> B：cpp的编译器一旦发现一个类型中有虚函数，就会为该类型生成虚函数表，并在该类型的每一个实例中添加一个指向虚函数表的指针。在32为的机器上，一个指针占4字节的空间，因此求`sizeof`得到4，如果是64位的机器，则一个指针占8字节的空间，因此求`sizeof`得到8。

这个具体怎么回事我就不解释了，如果有机会的话修订的时候就会把这个修订上。

### 面试题2 实现Singleton模式

大多数的面试都是围绕着数组、字符串、链表、树、栈以及队列这些数据结构展开的。

首先我们来讲数组。数组空间效率低是因为有空闲的内存没有得到利用；数组内存连续，可以在O(1)时间复杂度下读写数据，时间效率很高，所以我们可以用数组来实现简单的哈希表。除了C语言原本带的数组之外，cpp的STL 中还添加了vector，为了避免浪费，我们先为数组开辟较小的空间，然后往数组中添加数据，当数据的数目超过数组容量时，我们再重新分配一块更大的空间，把之前的数据复制到新的数组中，再把之前的内存释放。例如vector每次扩容的时候，新的容量都是之前的两倍。

同时为了让读者理解指针的概念，作者还给出了一个例子来了解数组和指针的区别。

```cpp
int GetSize(int data[]){
    return sizeof(data);
}

int main(int argc, char* argv[]){
    int data1[] = {1,2,3,4,5};
    int size1 = sizeof(data1);
    int* data2 = data1;
    int size2 = sizeof(data2);
    int size3 = GetSize(data1);
    printf("%d,%d,%d",size1,size2,size3);
}
```

`data1`是一个数组，那么他的大小就是数组数组中每个元素的大小（4字节）乘以元素个数（5个），data2是一个指针，指向了第一个元素的引用，那么一个指针的大小是8。在cpp中当数组作为函数参数进行传递的时候，数组就会自动退华为同类型的指针。因此`size3`的结果也是一个指针的大小为8字节。事实上这种写法会在cpp中弹出警告`warning: 'sizeof' on array function parameter 'data' will return size of 'int*' [-Wsizeof-array-argument]`，你也可以猜到他的大小为8字节。

### 面试题3 数组中重复的数字(1) 找出数组中重复的数字

> 在一个长度为$n$的数组里的所有数字都在$0\sim n-1$的范围内，数组中某些数字是重复的，但不知道有几个数字重复了，也不知道每个数字重复了几次。请找出数组中任意一个重复的数字。例如，如果输入长度为$7$的数组$\{ 2,3,1,0,2,5,3 \}$，那么对应的输出是重复的数字$2$或者$3$。

解法1：计数

我先说一下我的思路。很简单，我建立一个数组，下表代表了数字，里面的值代表对应的个数，从头到尾遍历一下原数组，然后每检测到对应的一个值就进行计数。最后再遍历一遍建立的数组，输出一个大于1的值就可以了。时间复杂度为$O(n)$，空间复杂度为$O(n)$。

解法2：排序

书上首先给出了一个思路，就是把输入的数组排序，然后从顺序排列的数组中遍历，如果后一个数和前一个数相等，不是严格大于或者小于的关系，那么就说明这个数字是重复的。时间复杂度为$O(n\log{n})$，空间复杂度为$O(1)$。

代码实现待补充

解法3：哈希表

书中的描述有些问题，我理解一下：首先建立一个哈希表，判断这个数字有没有出现过，遍历原数组，如果数没有出现过，那么就将哈希表中的值从false设置为true，如果已经出现（已经为true了）那就直接返回这个数就可以。时间复杂度为$O(n)$，常数比解法1略小，空间复杂度为$O(n)$。

解法4：官方解法

作者要给我们一种时间复杂度为$O(n)$、空间复杂度为$O(1)$的算法。注意到，数字的范围都是0到n-1，如果没有重复的数字，那么当数组有序的时候，下标数和里面对应的值应该相等。但是因为存在了重复的数字，那么有序的情况下，这个值会出现不对应的情况，下标数比里面的值要大（从小到大排序的话）。那么我们可以在数组遍历的过程中，把它放到自己应该在的位置，有没有比排序快的算法？很简单，我们每次遍历到下标i的位置上时，我们就看看下标和值是否相等，如果不相等，我们就把值换到他应该存在的位置，如果此时对应的位置上的值已经有了，这就说明找到重复的不用再往下进行了（原来的位置和正确的位置上都有一个），然后再进行这样的交换，这样的话每个数最多移动两次就到了自己对应的位置（被别人移走一次，自己到了新位置又一次），那么时间复杂度就是O(n)，由于我们没有用额外的数据结构来存储，那么空间复杂度就是O(1)。

上述思路的代码实现（原书中返回的是bool值，即是否有重复的数，重复的数字是直接给传给指针的）

```cpp
bool duplicate(int numbers[], int length, int* duplication){
    if(numbers == nuillptr || length <=0){
        return false;
    }
    for(int i=0;i<length;i++){
        // 类似的力扣题是这道题的题目2，他保证了输出所以不用判断不合法数组
        if(numbers[i]<0 || numbers[i]>length-1){
            return false;
        }
    }
    for(int i=0;i<length;i++){
        while(numbers[i]!=i){
            if(numbers[i] == numbers[numbers[i]]){
                *duplication = numbers[i];
                return true;
            }
            std::swap(numbers[i],numbers[numbers[i]]);
        }
    }
    return false;
}
```

### 面试题3 数组总重复的数字(2) 不修改数组找出重复的数字

> 再一个长度为$n+1$的数组里的所有数字都在$1\sim n$的范围内，所以数组中至少有一个数字是重复的，请找出数组中任意一个重复的数字，但不能修改输入的数组。例如，如果输入长度为$8$的数组$\{ 2,3,5,4,3,2,6,7 \}$，那么对应的输出是重复的数字2或3。

解法1：双循环枚举

这是我首先想到的方法。因为数字的范围是从$1$到$n$，那么直接从小到大遍历，如果碰到同一个数两次那么就直接返回那个数即可。由于是双层循环，时间复杂度为$O(n^2)$，不需要开新的数组，空间复杂度为$O(1)$ 。

代码待补充。

解法2：上一题的官方解法修改。

这是自然而然就能想到的，我们不在原数组里面交换，而是改成一个新的数组里赋值。逐一把原数组的每个数复制到辅助数组，将里面的值赋值到对应的下标中，如果已经存在，那么就说明重复了。时间复杂度为$O(n)$，空间复杂度为$O(n)$。

代码待补充。

解法3：官方解法。

我们可以让空间复杂度为$O(1)$吗？如果没有重复的数字，那么$1\sim n$的范围里一定只有n个数字。我们把数组分成两部分，$1\sim m$是一部分，$m+1 \sim n$是另一部分，如果有重复数字的话，那么要么是$1\sim m$的数字数目超过$m$，要么是$m+1 \sim n$的数字数目超过$n-m$。那么我们每次就把某个范围内的数全部统计，找出可疑得的那部分，直到这个范围变成只有那一个数。这个解法和解法一的区别在于，我不需要每一个数都计数，我只需要把对应半区的数记好了就可以了。计数复杂度为$O(n)$，分治复杂度为$O(\log{n})$，因此总的时间复杂度为$O(n\log{n})$，空间复杂度为$O(1)$。

我们以$\{2,3,5,4,3,2,6,7 \}$为例来分析，可以发现这种方法不能找到所有的重复数字，如图所示。

然后是示例代码，统计个数的部分使用一个`countRange`函数。而我实现middle的方法也和作者不一样，因此图解中的顺序和最后输出的结果也不同，不过都是正确的。

```cpp
int countRange(const int* numbers, int length, int start, int end){
    // 就这道题来说，在这里判断numbers是不是空指针就多余了
    if(numbers == nullptr){
        return 0;
    }
    int count = 0;
    for(int i=0;i<length;i++){
        if(numbers[i] >=start; && numbers[i]<=end){
            count++;
        }
    }
    return count;
}

int getDuplication(const int* numbers, int length){
    if(numbers==nullptr || lenth<=0){
        return -1;
    }
    int start = 1;
    int end = length -1;
    while(end>=start){
        int middle  = (end+start)/2;
        int count = countRange(numbers,length,start,middle);
        if(end == start){
            if(count>1){
                return start;
            }else{
                break;
            }
        }
        if(count> (middle-start+1)){
            end = middle;
        }else{
            start = middle +1;
        }
    }
    return -1;
}
```

### 面试题4 二维数组中的查找

> 在一个二维数组中，每一行都按照从左到右递增的顺序排序，每一列都按照从上到下递增的顺序排序。请完成一个函数，输入这样的一个二维数组和一个整数，判断数组中是否含有该整数。
>
> 例如：`{{1,2,8,9},{2,4,9,12},{4,7,10,13},{6,8,11,15}}`符合这个条件，如果在这个数组中查找数字7，则返回true，如果查找数字5，则返回false。

解法一：模拟

解法二：官方做法（右上）

首先，我们可以想到，在数组的中间位置，看一下对应的值，如果这个数比要查找的值要小，那么目标位置肯定在这个数位置的右侧或下侧，同理如果大的话就在左侧和上侧，但是这样的话下次查找的区域就是两个相互重叠的区域。有没有更简单的方法呢？假设我们选择右上角的数字，设为$m$，他就是当前行最大的数字和当前列最小的数字，设待查找数字为$x$，如果$m>x$，说明要找一个比$m$小的数字，那么这一列上的所有数字都不符合要求（$m$是这一列最小的数字），下次只需要从$m$的左侧开始查找。如果$m<x$，说明要找一个比$m$大的数字，那么这一行上的所有数字都不符合要求（$m$是这一行最大的数字），下次只需要从$m$的下侧开始找。如此往复直到$m=x$即可。
