## （一）运行你的第一个LLM模型

当我们在提到LangChain的时候，我们会提到两个东西。一个是作为组织的LangChain，还有就是作为开源框架的langchain。前者除了LangChain框架，还有LangGraph和Deep Agents等开源工具，以及LangSmith商业平台，但是本篇讲的是作为开源框架的langchain。

要使用LangChain，你需要python版本大于3.10，并在pip中安装`langchain`包。然后对于你想使用的AI供应商，你还需要安装对应的服务商langchain包，它们会实现LangChain的若干个标准接口来提供一致的API。例如想用openai，那么你就可以装`langchain-openai`，我们这里使用的是DeepSeek，因此只需要安装`langchain-deepseek`即可，其他的供应商列表可以参考[这个链接](https://docs.langchain.com/oss/python/integrations/providers/overview)。

安装好之后，我们就可以编写示例代码了（在你看到这篇文章的时候，这个APIKey就已经失效了，请自己申请）。

接下来我们来详细解释这个代码中的各个函数以及它所代表的含义。

在初始化一个agent之前，我们肯定要先初始化一个聊天模型，即chat model。在LangChain中，初始化模型的方法就是`langchain.chat_models`下面的`init_chat_model`方法，它能够返回一个`BaseChatModel`。该方法有以下两种用法。

当你的模型使用的是官方提供商（例如在DeepSeek官网的DeepSeek，或者在openai里面的gpt），你就可以直接传入模型名称，将`model`参数传入你想要的模型名称。这个模型名称有两种传法，要么是直接带上提供商前缀，例如`openai:gpt-5.5`，这种情况下LangChain就会直接去调用openai的API；要么你直接使用单独的裸模型名，例如`claude-opus-4-7`，此时他会根据前缀的特定映射关系去推断服务商，我们刚才使用的就是这个方法。不过它不能保证百分百成功，因此官方更加推荐第一种。完整的服务商对应列表参见[这里](https://reference.langchain.com/python/langchain/chat_models/base/init_chat_model)。

当你的模型使用的是非官方提供商，例如在硅基流动网站中使用gpt模型，那么你除了模型名称之外，还需要额外添加一个`model_provider`参数。例如：

```py
model =init_chat_model(
    model_provider='openai',
    # 硅基流动并不在官方支持的提供商列表中，要想使用的话直接填openai就可以了，别忘了安装langchain-openai
    model="deepseek-ai/DeepSeek-V3",
    api_key="", # 你的APIkey
    # 设置base_url为硅基流动
    base_url='https://api.siliconflow.cn/v1/'
)
```

除了这两个最重要的参数，还有一些常用的参数不在参数列表中，都是`**kwargs`来用的，例如刚才的`api_key`和`base_url`等，可以参考各个提供商对应的文档。

当我们声明完model之后，我们就可以创建一个agent了。`create_agent`是`lengchain.agents`里面的一个方法。其常用的参数如下。

- `model`，必传参数，类型为`str|BaseChatModel`，就是你要用的语言模型，如果你为了图方便，可以直接用没有任何额外参数的字符串（例如你的api-key放在了环境变量中），其推断方式和`init_chat_model`一样。不过大多数场合还是建议你直接传入一个已经声明好的模型。
- `tools`，传入可以给agent进行使用的工具，这些工具将在以后得文章中进行讲解。
- `system_prompt`，类型为`str|SystemMessage|None`，系统消息会被添加到调用模型时消息列表的开头。

在声明了agent之后，我们就可以调用这个agent了。可以看到他返回了一个字典，里面包含了消息列表。在Langchain中，模型上下文的基本单位是消息（Messages），模型的所有输入和输出都是借助一条条消息来实现的，消息分为四类，分别代表着四种不同的角色：system、user、tool和ai。他们对应的类和作用说明如下表所示。

| 角色名称 (Role) | 对应的类        | 作用说明                                                                                                 |
| --------------- | --------------- | -------------------------------------------------------------------------------------------------------- |
| system          | `SystemMessage` | 系统提示词。用于设定 AI 的“人格”、专业背景、行为准则或约束条件。它通常优先级最高，决定了后续对话的基调。 |
| user            | `HumanMessage`  | 用户消息。代表人类发送的内容。这是模型需要直接回答或处理的问题。                                         |
| ai              | `AIMessage`     | AI 消息。代表模型之前的回复。在构建多轮对话（带记忆）时，需要把模型之前的回复传回去。                    |
| tool            | `ToolMessage`   | 工具的执行结果，可以让模型看到或者直接呈现给用户。                                                       |

众所周知，大模型的输入通常是不可控的，即使你给了非常谨慎的提示词，他可能还是不会按照你想要的方式输出。

langchain目前支持以下几种结构化输出模式：

- Pydantic Model，这是一个第三方库，用于提供类似于`@dataclass`的功能，但是增加了强校验+自动转换的功能。
- Dataclass，这是高版本python中自带的一个数据类定义，性能上比Pydantic Model更加的优秀。
- TypedDict，也就是数据字典，这个写起来比dataclass麻烦一些，但是引入的比较早。
- JSON Schema，如果你的数据要与前面进行通信的话，那么这个无疑是最合适的选择。

在本文中，我们都使用JSON格式来进行操作。想要实现结构化输出，就需要`create_agent`函数中的`response_format`来参与了。这个参数提供以下三种策略。

首先是`ProviderStrategy`即提供者策略，一些模型提供商通过其API原生支持结构化输出，例如openai、Gemini等，本文中的DeepSeek也是支持的。我们传入的`ProviderStratergy`主要需要以下参数。

- `schema`，类型为`type[SchemaT]`，传入你用输出模式规定好的输出模板即可。
- `strict`，类型为`bool | None`，默认为`None`，代表你是否遵循严格模式（只有部分提供商支持）。

其次是`ToolStrategy`，当你的服务提供商没有原生的结构化输出能力时，就需要`ToolStrategy`出场了。同样的，我们传入的`ToolStrategy`也主要需要以下参数。

- `schema`，同上。
- `tool_message_content`，生成结构化输出时返回工具信息的自定义内容。
- `handle_errors`，模型输出不符合结构化时的处理方式，默认为`True`，包括以下几种。
  - `True`，用默认错误模板捕获所有错误。
  - `str`，也传入的字符串捕获所有错误。
  - `type[Exception]`，仅用默认消息捕获该种类异常类型。
  - `tuple[Exception]`，仅用默认消息捕获这些种类异常类型。
  - `Collable`，返回错误信息的自定义函数。
  - `False`，不重试，让异常传播。（等我复现出那个报错出来，然后再看怎么个事）

我们可以清楚的看到，此时结果作为`ToolMessage`输出，AI输出的信息为空字符串，同时在输出的值里面还有一个字段叫做`structured_response`。

目前我们的输出，都是等到大模型给出结果了，我们才进行输出。但是我们看到官网上的那些输出方式，都是流式输出。那么langchain也给出了如何进行流式输出的方式。

在最新版本的langchain（1.3.0）中，我们使用Event Streaming进行流式传输。例如：

```py
# main.py
from langchain.agents import create_agent
from langchain.chat_models import  init_chat_model

model = init_chat_model(
    model='deepseek:deepseek-chat',
    api_key = 'sk-9828462196484d9e9a5cde33cefaa0e1',
)
agent = create_agent(
    model=model,
    system_prompt="You are a helpful assistant",
)

stream = agent.stream_events({
    "messages": [
        {
            "role": "user",
            "content": "给我写一首诗"
        }
    ]
},version="v3")

for message in stream.messages:
    for delta in message.text:
        print(delta,end="",flush=True)
# 它就会不断更新输出的文本。
final_state = stream.output
print(final_state)
# 这里输出的是类似于之前一样的最终输出
```

`stream.messages`生成`ChatModelStream`对象，每个消息流会暴露`text`、`reasoning`、`tool_calls`和`output`四个属性。
